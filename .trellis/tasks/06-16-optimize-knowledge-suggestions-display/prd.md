# Optimize Knowledge Suggestions Display

## Goal

Make the knowledge suggestion page understandable for normal users. The main card should explain what the knowledge is, why it is worth saving, and how it helps later work. Technical trace IDs such as `commandRuns=...` and `gateRuns=...` should remain available for audit/debugging, but default to folded details.

## What I Already Know

- The current pending knowledge card shows raw evidence strings in the visible "为什么值得收录" field.
- Examples include `commandRuns=cmd_...` and `gateRuns=gate_...`, which are useful for traceability but unreadable for product users.
- The current page already has a folded "来源详情" panel with raw Run and evidence fields.
- The web app is a lightweight TypeScript DOM renderer with page-local state in `apps/web/src/page-knowledge.ts`.
- Frontend specs require user-facing Chinese copy and collapsed technical disclosures for raw diagnostics.

## Requirements

- Replace raw evidence strings in default-visible content with plain Chinese explanations.
- Keep raw evidence IDs available in a collapsed technical/source section.
- Show why the user should accept/edit/ignore a suggestion in product terms.
- Keep the page compact enough for scanning multiple suggestions.
- Preserve existing actions: accept, edit before accepting, ignore.
- Avoid changing backend contracts unless frontend display cannot solve the issue cleanly.

## Proposed Design

### Pending Suggestion Card

Top area:
- Title: short readable summary of the suggested knowledge.
- Subtitle: `决策/经验/模式/踩坑 · 来自 <任务名>`.
- Status chip: `待确认`, `已收录`, `已忽略`.

Readable body:
- Section label: `建议收录的知识`
- Content: the actual knowledge sentence, in Chinese-first readable prose.

Decision support grid:
- `为什么值得收录`: plain explanation derived from suggestion kind and evidence type.
- `后续怎么帮你`: existing future-value copy, adjusted for readability if needed.

Evidence summary row:
- Use small chips or short text, for example:
  - `已通过质量检查`
  - `有命令执行记录`
  - `来自本次任务`
- Do not show raw IDs in this row.

Actions:
- Primary or clear secondary buttons: `收录`, `编辑后收录`, `忽略`.

Collapsed details:
- Summary text: `查看技术来源`
- Include raw `Run`, `建议编号`, `证据`, `sourceRefs`, command/gate IDs.

### Copy Mapping

- `commandRuns=...` -> `本条建议来自实际执行过的验证命令，可用于证明这次结论不是凭空生成。`
- `gateRuns=...` -> `本条建议来自已通过的质量检查，可作为后续任务复用的可信经验。`
- `commandRun=...` with failed command -> `本条建议记录了一次失败或异常路径，后续遇到类似问题时可优先排查。`
- Unknown evidence -> `本条建议来自本次任务执行证据，收录后可帮助后续任务复用判断。`

### Accepted Knowledge Card

- Keep visible fields focused on usage:
  - `适用范围`
  - `最近引用`
  - `可信度/维护状态`
- Keep artifact IDs, URI, source refs, and run IDs inside `技术详情`.

## Acceptance Criteria

- [ ] Pending suggestion cards no longer show `commandRuns=` or `gateRuns=` in default-visible fields.
- [ ] Raw evidence IDs remain visible under a collapsed details panel.
- [ ] The card can be understood without knowing what command runs, gate runs, artifacts, or workflow runs are.
- [ ] Existing accept/edit/ignore behavior still works.
- [ ] Details panel open/closed state is preserved across polling renders via stable `data-details-key`.
- [ ] Typecheck for `@ainp/web` passes.

## Definition of Done

- UI copy is Chinese-first and user-facing.
- Technical details are audit-friendly but not default-visible.
- No new dependency is introduced.
- Existing backend data shape is preserved unless a focused frontend helper is insufficient.

## Out of Scope

- Redesigning the entire knowledge base page navigation.
- Changing how knowledge suggestions are generated by the API.
- Adding new backend evidence lookup endpoints.
- Changing knowledge acceptance persistence semantics.
