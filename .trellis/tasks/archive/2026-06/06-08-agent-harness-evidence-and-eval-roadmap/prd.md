# Agent Harness Evidence and Eval Roadmap

## Goal

Turn the current AI Native Platform from a workflow demo with logs and gates into a stronger Agent Harness: agent success claims must be backed by tamper-evident evidence, completion must be blocked by missing evidence, and later phases must add measurable evals, scoped gotcha knowledge, retro learning, and UI/Playwright verifier evidence.

## Background

The current architecture already matches the right direction:

- API Workflow Engine is the single state writer.
- Runner executes stages and real local commands in worktrees.
- Gate Engine, not the agent, decides pass/warn/fail.
- Context Pack already has budgeted selection and source refs.

The next improvement should not add more prompt text first. It should make success harder to fake and easier to measure.

## Scope

### Phase A - implement now

1. M1 evidence anti-forgery foundation:
   - Compute SHA-256 digests for command stdout/stderr logs.
   - Compute SHA-256 digests for file artifacts recorded by the API/runner.
   - Persist digest metadata across shared types, SQLite rows, API detail responses, and tests.
   - Expose digest verification when reading command logs and artifact content.

2. M2 unified Evidence Gate:
   - Add a gate that validates persisted evidence before completion.
   - Require pass GateRun rule evidence to resolve to persisted evidence records.
   - Require compile/test gates to cite resolvable, digest-bearing command evidence.
   - Require acceptance to have at least one implementation/test/log/artifact evidence path.
   - Run the Evidence Gate before Completion Report generation.

3. Self-test guidance:
   - Provide explicit commands and expected checks for local verification.
   - Keep the self-test path runnable without external services where possible.

### Phase B - incremental foundation and follow-up plan

4. M4 Eval Harness:
   - Fixed scenario schema.
   - JSON/HTML result output.
   - A/B support for knowledge/skill variants and backend comparisons.
   - Current increment: deterministic local `bun run eval` harness with scenario variants and JSON/HTML reports.

5. M5 Knowledge refinement:
   - Convert accepted knowledge injection from full markdown concatenation toward scoped top-N gotcha/decision/pattern entries.
   - Track evidence refs, status, hit count, and stale/suspect signals.
   - Current increment: runner skips legacy unbounded accepted-knowledge markdown when structured KnowledgeArtifacts are available, leaves ContextPack selection to score/bound structured entries, and records selected structured-knowledge usage through `POST /knowledge-artifacts/usage` with `hitCount`, `lastUsedAt`, and ContextPack provenance metadata.

6. M6 Retro loop:
   - Generate a retro artifact per run from persisted events/gates/logs.
   - Convert confirmed retro findings into knowledge or eval candidates.
   - Current increment: API `POST /workflow-runs/:id/retro` generates fact-first markdown + JSON sidecar retro artifacts from persisted run evidence, and `POST /workflow-runs/:id/retro-actions` records human-confirmed knowledge-review actions or digest-backed eval scenario draft artifacts.

7. M3 Verifier / Playwright evidence:
   - Add a verifier stage or verifier sub-stage.
   - Support AC-to-evidence matrices and before/after screenshot/video artifacts for UI tasks.
   - Current increment: runner adds a review-stage verifier sub-stage for UI tasks, persists verifier media and AC-to-evidence matrix artifacts through `/runner/events/artifact`, and runs Evidence Gate before human acceptance so UI runs fail when required verifier matrix/media refs or SHA-256 digests are missing. Verifier media must be explicitly tagged; generic image artifacts do not satisfy the verifier. No Playwright dependency or browser runtime was introduced in this pass.

## Out of Scope for Phase A

- No new third-party dependencies.
- No full Eval Harness implementation in this pass.
- No new flow stage in this pass unless Evidence Gate requires a narrow engine-side hook.
- No Playwright runtime integration in this pass.
- No UI redesign beyond digest/evidence visibility needed for operator self-test.

## Requirements

### R1 Command evidence digests

Every new `CommandRun` generated by `runWhitelistedCommand()` must include SHA-256 digests for stdout and stderr logs, plus a combined digest derived from both streams. Digests must be deterministic and stored with the command run.

### R2 Artifact evidence digests

Every file artifact created through the normal API/runner path must include SHA-256 digest metadata when the file is readable at ingest time. Non-file artifacts may keep digest fields null.

### R3 Digest verification surfaces

Artifact content and command log read endpoints must return whether the current file content still matches the stored digest. A missing digest should be explicit rather than silently reported as verified.

### R4 Evidence Gate

Before completion report generation, the platform must run a unified `evidence_gate`. It must fail when a previously passing gate has no resolvable evidence refs, when compile/test gates lack resolvable command evidence or command digests, or when acceptance has no implementation/test/log evidence path.

### R5 Backward compatibility

Existing database rows without digest fields must still load. Missing digests should not crash list/detail routes; they should cause Evidence Gate to warn/fail only where the rule requires digest-backed proof.

### R6 Tests

Add unit/route tests covering digest calculation, digest mismatch detection, and Evidence Gate pass/fail behavior.

## Technical Notes

- Shared command/artifact types live under `packages/shared/src/types/`.
- Runner command execution lives in `apps/runner/src/command-runner.ts`.
- API artifact/log read surfaces live in `apps/api/src/routes/artifacts.ts`, `apps/api/src/routes/command-runs.ts`, and `apps/api/src/artifact-content.ts`.
- Gate logic lives in `apps/api/src/gate-engine.ts`.
- Orchestration completion logic lives in `apps/runner/src/orchestrator.ts` and API completion report route.
- Store migrations live in `apps/api/src/store/db.ts`; row mapping lives in `apps/api/src/store/store.ts`.

## Risks

- Digest fields touch shared types, DB, API, runner, and web DTOs. Mitigation: keep digest fields optional/null-safe for backward compatibility.
- EvidenceRef currently points at `artifactId` but is used for CommandRun ids in some gates. Mitigation: Evidence Gate should resolve against both artifacts and command runs unless/until the model is split.
- Completion preflight may break old tests that construct minimal gates without evidence. Mitigation: update tests to include evidence where success is claimed.

## Follow-up Roadmap

1. Expand Eval Harness beyond deterministic router scenarios by adding workflow fixture and fake backend fixture scenario kinds.
2. Continue Knowledge refinement by using `hitCount` / `lastUsedAt` in ranking and stale-review workflows after enough usage telemetry exists.
3. Extend M3 from verifier evidence contract to automatic Playwright capture: install the minimal Playwright dependency, capture before/after screenshots or videos, and feed those files into the existing `.ainp-verifier` / artifact-ingress path.
