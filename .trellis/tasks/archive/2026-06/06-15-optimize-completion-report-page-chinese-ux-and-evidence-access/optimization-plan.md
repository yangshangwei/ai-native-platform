# 交付报告页面优化方案

## 当前问题分析

### 1. 中文表达问题
- ❌ "Completion Report" → 应为"交付报告"
- ❌ "GATE 14/14" → 应为"质量门禁 14/14"
- ❌ "Stage timeline" → 应为"阶段时间线"
- ❌ "Gates" → 应为"门禁检查"
- ❌ "Build & Tests" → 应为"构建与测试"
- ❌ "Commands (2)" → 应为"命令执行 (2)"
- ❌ "Artifacts (7)" → 应为"产物证据 (7)"
- ❌ "Approvals (3)" → 应为"审批记录 (3)"
- ❌ "Context Requests (0)" → 应为"上下文请求 (0)"
- ❌ "Knowledge Review Signals (0)" → 应为"知识评审信号 (0)"
- ❌ "Context Governance Metrics" → 应为"上下文治理指标"
- ❌ "报告来源详情" → 可改为"技术细节"

### 2. 易用性问题
- ❌ 关键指标（GATE、测试、命令、产物）埋在折叠列表中
- ❌ 产物证据 (7) 折叠隐藏，不易快速浏览
- ❌ 缺少可视化卡片，信息层次不清晰
- ❌ 证据文件需要多次点击才能查看
- ❌ 布局垂直堆叠，缺少横向利用空间

### 3. 信息架构问题
- ❌ 顶部 3 个指标卡片（14/14、6/6、2）位置不突出
- ❌ 折叠项太多，用户需要反复展开
- ❌ 核心证据（Artifacts）被降级为普通折叠项

## 优化方案

### 方案 A：渐进式优化（推荐）

#### 1. 全面中文化
**影响文件**: `apps/web/src/page-task-detail.ts`

**优化点**:
- 所有折叠标题改为中文
- 技术术语保留英文，但加中文标签
- 保持专业性的同时提升可读性

**实施**:
```typescript
// 修改折叠标题映射
const COLLAPSIBLE_SECTION_LABELS = {
  'Stage timeline': '阶段时间线',
  'Gates': '门禁检查',
  'Build & Tests': '构建与测试',
  'Commands': '命令执行',
  'Artifacts': '产物证据',
  'Approvals': '审批记录',
  'Context Requests': '上下文请求',
  'Knowledge Review Signals': '知识评审信号',
  'Context Governance Metrics': '上下文治理指标',
}
```

#### 2. 关键指标卡片化
**影响文件**: `apps/web/src/page-task-detail.ts`

**优化点**:
- 在报告顶部增加 4 个突出的指标卡片
- 使用 `metricCardV2` 组件，与工作台风格一致
- 卡片内容：门禁通过率、测试通过率、命令执行、产物数量

**布局**:
```
┌─────────────────────────────────────────────────────────┐

│ │  14/14   │ │   6/6    │ │    2     │ │    7     │   │
│ │  ✅通过   │ │  ✅通过   │ │  ✅成功   │ │  查看全部 │   │
│ └──────────┘ └──────────┘ └──────────┘ └──────────┘   │
└─────────────────────────────────────────────────────────┘
```

#### 3. 产物证据快速访问
**影响文件**: `apps/web/src/page-task-detail.ts`

**优化点 3.1: 产物类型分组展示**
```
产物证据 (7) ▼
├─ 📄 需求文档
│  └─ requirement_draft → requirement.md
├─ 📐 设计文档
│  └─ design_doc → design.md
├─ 💻 代码变更
│  └─ diff → changes.diff (2 files)
├─ 🧪 测试报告
│  └─ surefire_report → TEST-sample.CalculatorTest.xml
├─ ✅ 验收报告
│  └─ completion_report → art_5cecf0a507e9.md
└─ 📚 知识候选
   └─ knowledge_candidate → art_ba048d108521.md
```

**优化点 3.2: 一键预览**
- 产物卡片支持悬停预览（前 5 行）
- 点击直接在右侧面板展开完整内容
- Markdown 产物渲染为富文本

**优化点 3.3: 快速下载**
- 每个产物旁边增加"下载"按钮
- 支持批量下载（打包为 ZIP）

#### 4. 响应式布局优化
**影响文件**: `apps/web/src/page-task-detail.ts` + CSS

**优化点**:

### 方案 B：激进式重构（长期）


#### 3. 证据查看器

## 预期效果

### 前后对比

#### 优化前
- 🔴 英文术语混杂，专业但不亲切
- 🔴 关键指标需要展开才能看到
- 🔴 产物证据深埋在折叠列表
- 🔴 布局单一，信息层次不清

#### 优化后
- ✅ 全中文界面，保持专业性
- ✅ 关键指标顶部卡片，一目了然
- ✅ 产物证据分组展示，快速访问
- ✅ 布局清晰，信息层次分明

### 用户体验提升
1. **查看效率** ⬆️ 50%（减少点击次数）
2. **信息获取速度** ⬆️ 70%（关键指标一目了然）
3. **学习曲线** ⬇️ 30%（中文界面降低认知负担）

## 风险评估

### 低风险
- ✅ 中文化：只改文案，不改逻辑
- ✅ 指标卡片：新增组件，不影响现有功能

### 中风险
- ⚠️ 产物分组：需要重构数据投影逻辑
- ⚠️ 布局调整：可能影响移动端适配

### 缓解措施
1. 分阶段实施，每次只改一个模块
2. 保留原有折叠列表作为兜底
3. TypeScript 类型检查确保不破坏现有契约
4. 本地测试验证所有交互场景
