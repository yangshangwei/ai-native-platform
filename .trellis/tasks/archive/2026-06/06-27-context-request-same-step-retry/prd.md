# Context Request Same-step Retry

## Goal

Implement Epic C from the Agent Runtime docs: when an agent emits a structured `context_request`, the Runner should build a supplement ContextPack and retry the same skill once within the same step, linking the retry AgentSession to the base AgentSession.

## Requirements

1. Extend context supplement metadata so a supplement pack records the request id, base pack id, and retry index.
2. `invokeSkill()` must detect a captured `context_request`, finish the base invocation with trace metadata, and retry the same skill once using the supplement ContextPack.
3. The retry invocation must create its own AgentTask and AgentSession, with `parentSessionId` pointing at the base session and `retryIndex = 1`.
4. If the retry also emits a `context_request`, the Runner must stop instead of looping forever, mark the retry session failed, and throw a clear error.
5. If sensitive path filtering removes all requested context, the Runner must not retry.
6. Existing no-context-request success behavior must remain unchanged: callers still finish the returned invocation through `finishAgentSuccess()`.
7. The deterministic fake backend eval scenario should cover first-call context_request then second-call success without real CLI dependencies.

## Acceptance Criteria

- [x] Shared/context tests prove supplement metadata includes `retryIndex`.
- [x] Runner tests prove first invocation context_request triggers exactly one same-step retry.
- [x] Runner tests prove retry AgentSession uses `parentSessionId` and `retryIndex = 1`.
- [x] Runner tests prove repeated context_request after retry limit fails and does not leave the retry session running.
- [x] Runner tests prove sensitive-only context_request is filtered and does not retry.
- [x] `bun run eval` passes with the fake backend context_request variant.
- [x] `bun test packages/shared/test apps/runner/test` passes for touched surfaces.
- [x] `bun run typecheck` passes.

## Out of Scope

- Multi-retry policies beyond one bounded same-step retry.
- Human-in-the-loop resolution for insufficient supplement context.
- ToolInvocation, Handoff, or Memory Lifecycle changes.
- UI changes for retry chains.

## Technical Notes

- Keep Workflow Engine and API state writes behind Runner event APIs.
- AgentSession status remains invocation audit state, not gate status.
- The base invocation can be finished as `success` because it successfully produced a structured context_request; the retry result determines whether the skill returns a final InvokedAgent to downstream orchestration.
- The retry ContextPack should be the supplement pack generated by `buildIncrementalContextPack()`, not a fresh ordinary base pack.
- Existing `ContextRequestCapture` can carry the supplement pack internally for retry orchestration.

## Definition of Done

- C1-C3 behavior is implemented and covered by red/green tests.
- Relevant specs are updated with the retry contract.
- Trellis task is validated, committed, archived, and session-recorded without staging unrelated dirty Trellis files.
