为什么需要「可验证」的 AI 交付？

让 Agent 写代码很容易，让它说自己写对了更容易—— 难的是在不信任 Agent 自我报告的前提下，依然能把交付推进到底。

Agent 自报 ≠ 事实

LLM 说「测试通过」不等于测试真的跑了。本平台的 Build/Test 来自 Runner 实际 spawn 的 mvn，证据是 exitCode + 解析后的 Surefire XML。

状态写入失控

谁都能推进流程，状态就不可信。这里 Workflow Engine 是唯一状态写入者，Runner 只发事件，Agent 没有任何状态写入路径。

交付无据可查

没有报告就没有验收。每次交付都自动从 SQLite 拼装 Completion Report，引用每个 Artifact、Gate、CommandRun。

标准功能流，每步都有把关

一条流水线串起从需求到知识沉淀的全过程。绿色阶段产出 Artifact，灰色菱形是必须通过的 Gate。

1context_pack上下文打包
2requirement需求草稿 + Gate
3design设计 + 人工批准
4implementationAI 开发 + Diff Gate
5build_test真实 mvn 编译测试
6review验收 Gate
7completionCompletion Report
8knowledge知识候选入库

所有产物（Artifact、CommandRun、BuildRun/TestRun、GateRun、Approval、AuditLog）持久化到 SQLite， 可被 Web UI 和 Completion Report 引用。

平台编排生命周期，不只是调 Agent

⚙

Workflow Engine 唯一写入

状态只有一个入口。Runner 发事件、路由调 engine，Agent 越权无门。流程因此可信、可审计。

🛡

Gate Engine 把关

每个 GateRun 由 gate-engine 判定 pass/warn/fail：Diff Scope、Sensitive Change、Compile、Test、Acceptance。Agent 只能附注，不能改 status。

🧪

真实构建测试

Runner 实际跑 mvn -B -DskipTests compile → mvn -B test，TestRun 来自解析的 Surefire XML，不是 LLM 自报。

🌿

本地 Worktree 执行

每个 WorkflowRun 一个独立 Git worktree，用本机 JDK / Maven / Git 环境编译测试。隔离代码工作区，贴近真实开发。

📄

Completion Report

每次交付自动拼装 markdown 报告，逐条引用 Artifact / Gate / CommandRun，验收有据可查。

🧠

知识沉淀

经验先生成 Knowledge Candidate，由 Knowledge Gate（人工）决定是否入库，沉淀可复用资产。

可插拔的执行后端

Skill 属于平台，Claude Code 与 Codex 只是执行后端。项目配置里选择其一， Runner 启动任务前先做 CLI preflight，失败直接给出安装/登录修复提示。

CCClaude Code

真实 CLI Agent Backend，流式事件回传，按阶段注入平台 SkillSpec。

CXCodex

同一套适配契约，跨平台 CLI 解析；Windows 优先尝试 shim 与可执行文件。

需要固定路径时设置 AINP_CLAUDE_BIN / AINP_CODEX_BIN， preflight 通过的解析结果会原样传给 Runner 运行时执行。
