一句话需求，到可被证明的交付。

AI Native Platform 把软件交付收敛成可审计的流程编排：需求 → 设计 → AI 开发 → 构建测试 → 验收 → 报告 → 知识沉淀。Agent 只写代码，不能跑命令、不能推进状态—— 构建测试由 Runner 白名单命令执行，支持任意构建工具，每次交付都生成 Completion Report。

为什么需要「可验证」的 AI 交付？

让 Agent 写代码很容易，让它说自己写对了更容易—— 难的是在不信任 Agent 自我报告的前提下，依然能把交付推进到底。

Agent 自报 ≠ 事实

LLM 说「测试通过」不等于测试真的跑了，测试真的跑了也不等于业务验收。本平台的构建测试来自 Runner 白名单命令实际 spawn，而验收要求每条 AC 都有具体业务证据——"命令跑过"类 AC 被自动拒绝。

状态写入失控

谁都能推进流程，状态就不可信。这里 Workflow Engine 是唯一状态写入者，Runner 只发事件，Agent 没有任何状态写入路径。

交付无据可查

没有报告就没有验收。每次交付都自动从 SQLite 拼装 Completion Report，引用每个 Artifact、Gate、CommandRun。

图驱动流程编排，每步都有把关

5 种流程模板覆盖功能开发、快速迭代、Bug 修复、重构和项目画像。每个写代码的流程都包含 build_test 阶段。 以下是最完整的 feature.standard——

1context_pack上下文打包
2requirement需求草稿 + Gate
3design设计 + 人工批准
4implementationAI 开发 + Diff Gate
5build_test白名单命令编译测试
6reviewAC 矩阵验证 + 人工验收
7completionCompletion Report
8knowledge知识候选入库

除 feature.standard 外，还有 feature.fastforward（4 阶段快速通道）、 issue.standard（Bug 修复）、refactor.standard（重构）、 profile.bootstrap（项目画像）共 5 条注册流程。 所有产物持久化到 SQLite，可被 Web UI 和 Completion Report 引用。

平台编排生命周期，不只是调 Agent

⚙

Workflow Engine 唯一写入

状态只有一个入口。Runner 发事件、路由调 engine，Agent 越权无门。流程因此可信、可审计。

🛡

Business Acceptance Matrix

测试通过 ≠ 业务验收。每条 AC 必须有证据证明业务行为——Verifier 逐条构建证据矩阵（core / boundary / exception 场景全覆盖），"命令跑过"类 AC 被自动拒绝。

🧪

白名单命令构建

项目可配置任意构建/测试命令（Maven、Gradle、npm、Cargo…），Runner 通过 runWhitelistedCommand 执行，Agent 的 Bash 工具被显式禁用——只有平台能跑命令。

🌿

本地 Worktree 执行

每个 WorkflowRun 一个独立 Git worktree，用本机构建工具链编译测试。隔离代码工作区，贴近真实开发。

📄

Completion Report

每次交付自动拼装 markdown 报告，逐条引用 Artifact / Gate / CommandRun，验收有据可查。

🧠

知识沉淀

经验先生成 Knowledge Candidate，由 Knowledge Gate（人工）决定是否入库，沉淀可复用资产。

可插拔的执行后端

Skill 属于平台，Claude Code 与 Codex 只是执行后端。项目配置里选择其一， Runner 启动任务前先做 CLI preflight，失败直接给出安装/登录修复提示。

CCClaude Code

真实 CLI Agent Backend，流式事件回传，按阶段注入平台 SkillSpec。Bash / Skill 工具被显式禁用——Agent 只能写代码，不能执行命令。

CXCodex

同一套适配契约，跨平台 CLI 解析；同样隔离 Agent 与命令执行层。Windows 优先尝试 shim 与可执行文件。

需要固定路径时设置 AINP_CLAUDE_BIN / AINP_CODEX_BIN， preflight 通过的解析结果会原样传给 Runner 运行时执行。

交付证据，看得见

从 Gate 看板到 Stream 日志，再到 Completion Report —— 每一份证据都可在 Web UI 下钻。
